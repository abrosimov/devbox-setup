# Structured fuzz inputs

Construct inputs that can exercise the authorised target and preserve them for replay. Begin with
the input contract, existing useful examples and available observations. PBT generator bridges,
mutation analysis and production-code bypasses are outside this workflow; ordinary fuzz-input
mutation remains an available operation.

## Choose the smallest useful construction

Inspect or replay a bounded sample before prescribing structure. For unfamiliar material, name
the sample, feasible operation, possible learning contribution and effort limit. Reconnaissance
may form the question; a precise hypothesis and pre-proven usefulness are not prerequisites.

| Material or obstacle | Candidate operation | Condition to preserve |
|---|---|---|
| Opaque bytes or lenient format | Existing seeds and native byte mutation | Intentional invalid/boundary cases still reach their relevant checks |
| Tokens or delimiters | Representative seeds or a supported dictionary | Verify that the actual engine uses the dictionary |
| Recursive syntax | Bounded grammar expansions | Limit depth, size and generation work; ensure a terminating construction |
| Dependent length/checksum fields | Construct or repair the dependent fields in the harness/generator | Replay applies the same transformation; retain an invalid-input route |
| Typed values or operation sequences | Deterministic byte decoder with bounded collections/sequence length | Account for exhaustion, reset state and preserve existing contract checks |
| Compressed wrapper | Authorised inner target or bounded repair/recompression | State which wrapper behaviour the experiment omits |

An adequate existing seed set can finish the construction task. Poor reachability does not force
a grammar or custom mutator; a bounded trial can establish whether one helps. Read
[Grammar, repair and reduction](references/grammar-and-repair.md) when grammar generation,
dependent fields or structured reduction is needed.

## Construct and examine

1. Determine the expected syntax and semantics from the actual contract. Select existing valid
   examples, intentional rejections and boundaries; keep unknown format details explicit.
2. Choose a feasible construction and state the observation it can supply. Bound generated bytes,
   recursion, collections, operation count and repair work before executing it.
3. Make decoding and replay deterministic under recorded versions and configuration. Preserve
   raw engine inputs as well as any useful readable decoded form. Define rejection/exhaustion
   behaviour; do not swallow unexpected exceptions or silently change the target's contract.
4. Replay independently expected examples through the actual target and observation method.
   Record acceptance separately from reached product behaviour and grammar alternatives exercised.
   Syntactic validity alone does not establish deeper reachability.
5. Retain useful generated and intermediate inputs, including non-crashing seeds, with provenance
   and replay commands/status. Preserve malformed-input exploration where it belongs to the contract.
6. Return the material and observed distinctions to the current investigation: answer its question,
   form a new in-scope question, choose a justified further examination, or finish with a limit.
   A new question need not reopen an unrelated closed one or erase earlier cost.

The relevant language harness must accept the produced representation. Verify this join: supply
the actual input files, encoding, decoder/configuration, expected behaviour and evidence of replay.
A diagram of a generator or a successfully built decoder is not proof that the product was exercised.

## Reduce and resume

For a failure, preserve the original and define the same-symptom predicate. Try bounded reductions
appropriate to the structure, replaying candidates independently. Keep the last verified candidate;
an environmental error, changed symptom or interrupted check does not establish a valid reduction.

Record the predicate, original/current inputs, completed reductions and unfinished check before
returning. A later session restores and performs that operation after checking affected target,
decoder and oracle assumptions. It does not restart reduction merely because the session changed.

Do not modify product validation to make generated inputs acceptable. Report the construction,
observed reachability, retained inputs, actual effort and limits. Grammar coverage is not code
coverage, a saturation certificate or evidence that the product is correct.
